### В2.2 Семантический поиск — гибрид FTS+embeddings, опционально

Поиск умеет косинусную близость эмбеддингов поверх FTS-lite. Фича целиком
opt-in: без `EMBED_URL`/`EMBED_KEY` поведение byte-identical 0.14.x (чистый FTS).

- 🧠 **`app/embed.py` (чистый stdlib, инъекция http как у observer)**: env
  `EMBED_URL` (OpenAI-compatible `/embeddings`, base или полный путь),
  `EMBED_KEY`, `EMBED_MODEL` (default `text-embedding-v3`), `EMBED_TIMEOUT`
  (default 10с), `EMBED_REFRESH_SEC` (default 300с), `EMBED_DAILY_CAP`
  (default 200k токенов/день, оценка len/4), `HYBRID_VECTOR_WEIGHT`
  (default 0.35, клэмп [0,1]). Fail-open: любая ошибка (сеть/HTTP/битый
  ответ/битый файл) → None + один `log.warning` на класс сбоя за сессию.
- 💾 **Хранилище `data/embeddings.json`**: `{name: {"v": [...], "u": updatedAt}}`,
  атомарная запись (tmp+replace; падение посреди — старый файл цел), ленивая
  инвалидация по `updatedAt`, сироты (удалённые из графа) выметаются. Вектора
  нормализуются при сохранении → косинус = dot product (чистый `math`/`operator.mul`).
  In-memory кэш по (path, mtime, size) — поиск не парсит JSON на каждый запрос.
- 🔁 **Фоновый пополнитель** (`embed_loop`, daemon-поток как observer): батчи
  ≤32 текста (name+title+первые 3 факта, ≤1000 chars), дневной кап в
  `data/embed.state.json` (ролл по UTC; кап → пауза до завтра, один warning/день),
  запись хранилища ОДИН раз в конце тика (не O(n²) на начальном заполнении),
  события в пульс НЕ пишутся (без спама). READONLY-зеркало: пополнитель не
  стартует, гибридный поиск при этом работает (вектора можно завезти ресинком).
- 🔀 **Гибрид в `searchrank.rank`** (`vector_weight`, `cosine_fn` — keyword-only,
  инъекция): `score = (1−w)·fts_norm + w·cos_norm`; `fts_norm = fts/max(fts)`
  по кандидатам, `cos_norm = (cos+1)/2`; нет вектора → нейтраль 0.5 (не штраф);
  клэмп кривого cos в [−1,1]; сбой cosine_fn → 0.5 (поиск не роняется).
  **Предфильтр** (задокументированный выбор): косинус считается только по FTS
  top-200 — полный проход 10k×1024 dims на чистом stdlib ≈ 0.5–1с, а
  200×1024 ≈ +7мс. Цена: векторно-only совпадения без FTS-пересечения не
  поднимаются (recall-стадия = FTS). `w=0`/без cosine_fn → чистый FTS
  byte-identical. В гибридном режиме `score` ответа — blended 0..1.
- 🔎 **Запрос эмбеддится синхронно** (как `_load()` в op_search): LRU 128 по
  (query, model), промах = один вызов с `EMBED_TIMEOUT`; токены запроса идут
  в тот же дневной кап (кап/сбой → чистый FTS).
- 🔒 **Изоляция проектов сохраняется**: корпус фильтруется (Ф1/Ф3) ДО обоих
  скорингов — `cosine_fn` вызывается только для имён видимого корпуса.
- 📖 docs/API.md: блок «Семантический поиск (В2.2)» + `embeddings.json`/
  `embed.state.json` в файлах данных; docker-compose — проброс `EMBED_*`/

- ✅ Тесты: **566/566** (+62 к 504): test_embed.py — конфиг/env, fail-open,
  форма запроса, index-порядок, косинус/нормализация, хранилище (roundtrip,
  атомарность при падении посреди записи, кэш), LRU запроса (128, модель в

### В2.3 ACT-R reinforcement — частые факты всплывают

Аналог ACT-R у claude-mem: память сама учится, что важно. Сущности, к которым
агент обращается чаще и недавнее, получают буст к рангу — без единой записи в
`memory.json` на чтении (никакого fsync-шторма и сдвига `updatedAt`).

- 🧠 **`app/actr.py` (чистый stdlib)**: упрощённый ACT-R base-level по агрегату
  `{n, last_ts}` (вместо полной истории `ln(Σ tᵢ⁻ᵈ)`):
  `множитель = 1 + min(ln(1+n) · 0.5^(дни/ACTR_HALF_LIFE_DAYS), 1.0) · ACTR_MAX_BOOST`
  — потолок +25% (default `ACTR_MAX_BOOST=0.25`, полураспад 14 дней);
  `n=0` → ровно ×1.0 (нейтраль, поведение не меняется ни на эпсилон).
- ✋ **Учитываются только «осмысленные» чтения**: `search_nodes` (top-20 выдачи),
  `open_nodes` (найденные), `session_start` (сущности, попавшие в `context_block`
  после бюджетной обрезки — построчный учёт). `read_graph` и пустой `query`
  (дамп корпуса) НЕ считаются — это не сигнал интереса к конкретным фактам.
- 💾 **In-memory счётчики + атомарный flush**: `{name: {"n", "t"}}` в памяти
  (leaf-лок на read-modify-write — GIL сам по себе инкременты теряет: регрессия
  10 потоков × 1000 касаний = ровно 10000), запись в `data/access.json`
  (tmp+replace) раз в `ACTR_FLUSH_SEC` (default 300с, daemon-поток как
  observer/embed) + финальный flush на shutdown (atexit). Загрузка при старте;
  битый/отсутствующий файл → с нуля (fail-open, один warning). Пульс НЕ пишется,
  события flush — тоже нет (без спама). READONLY-зеркало: flush не стартует,
  буст работает по завезённому ресинком `access.json`.
- 🔀 **Применение**: `searchrank.rank(..., actr_fn=…)` — новый keyword-only
  параметр-инъекция (как `cosine_fn` В2.2): множитель домножает итоговый скор
  (FTS или blended) до среза топ-N, сбой/NaN/≤0 → нейтраль 1.0 (fail-open);
  без `actr_fn` — byte-identical. В `session_start` сортировка внутри секций
  решений/багов/задач — актуальность (свежесть × множитель); сессии остаются
  чистой хронологией. **Default ON; `ACTR_MAX_BOOST=0` — полное отключение**
  (rank вызывается без `actr_fn`, поведение byte-identical 0.14.x/В2.2).
- 🔒 **Изоляция проектов сохраняется**: счётчики глобальны по имени, но имена
  сущностей глобально уникальны (merge по имени), буст применяется ПОСЛЕ фильтра
  корпуса (Ф1/Ф3) и только к видимым именам — утечки через буст нет.
- 📖 docs/API.md: блок «ACT-R reinforcement (В2.3)» + `access.json` в файлах
  данных; docker-compose — проброс `ACTR_FLUSH_SEC`/`ACTR_MAX_BOOST`/
  `ACTR_HALF_LIFE_DAYS` (пустые default'ы, паттерн `OBSERVER_*`).
- ✅ Тесты: **607/607** (+39 к 568): test_actr.py — конфиг/env (default, мусор,
  клэмпы, `ACTR_MAX_BOOST=0`), формула (n=0 → ×1 ровно, рост ln(1+n),
  recency 0.5^(дни/14), кэп +25%), flush/load roundtrip + атомарность + битый
